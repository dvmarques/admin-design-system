## Decisões de arquitetura e compatibilidade (perfil Critical)

1. Usar `develop` já integrada após PRs #266/#270 como base. Alterar manifestos, lockfile e somente configs/testes que precisarem de compatibilidade; nenhuma atualização indireta de runtime `@dvmarques/admin-ds-*`.
2. **TypeScript 6**: migrar primeiro para 6.0.3; o parser do `typescript-eslint@8.72.1` ainda restringe `<6.1`. Inspecionar `tsconfig.base.json`, declarações, aliases e `moduleResolution: Bundler`; conferir `noEmit`, `skipLibCheck`, geração `.d.ts` e exports. Se incompatível com gerador/Storybook, documentar bloqueador e manter TS5 até correção justificada, sem instalar TS7 à força.
3. **Vitest 5**: alinhar runner e coverage em 5.0.5 e garantir Vite >=6.4. A mudança oficial de default `clearMocks: true` pode alterar históricos entre testes; preservar comportamento anterior com `clearMocks: false` explícito inicialmente para não alterar sem intenção a suíte do projeto, corrigindo testes não isolados quando demonstrado. Conferir `vi.mock` top-level, projetos, timeouts, reporters e padrões de coverage. Verificar scripts que executam Vitest na raiz e nos workspaces.
4. **jsdom 30**: CI usa Node 24 atualizado, mas jsdom requer pelo menos 24.15 na linha 24. Diferenciar requisito de **ferramenta de desenvolvimento** do contrato público `engines.node >=24.0.0`; não elevar restrição da biblioteca. Inspecionar DOM, eventos, acessibilidade e snapshots gerados por teste.
5. **lint-staged 17**: manter configuração versionada na raiz e hook Husky sem adicionar novos efeitos colaterais; verificar lint/format e execução em arquivos staged em ambiente de teste isolado. `npm ci --ignore-scripts` na CI não invoca hooks; validar explicitamente.
6. **npm/lockfile**: npm 11.19.1 com Node 24; evitar editar transitive graph à mão. Comparar `npm outdated`, `npm ls`, `npm audit --json` e `--omit=dev` antes/depois no mesmo ambiente, versões e data. Os 14 avisos moderate herdados da #266/#270, por `glob` e `minimatch`, não são ausência de risco; não aplicar `npm audit fix --force` sem compatibilidade e evidência.
7. **Contratos públicos**: nenhuma alteração de classes `ads-`, tokens `--ads-`, APIs `Ads*`, limites Client/Server, estilo distribuível, dependências do runtime ou peer React; verificação de tarballs consumidos por Next externo e geração de API Storybook.
8. **Validação e rollback**: executar `npm ci --ignore-scripts`, `npm ls --depth=0`, `npm run format`, `npm run lint`, `npm run build`, `npm run typecheck`, `npm run test:quality`, `npm run test:coverage`, `npm run inspect:packages`, `npm run verify:optional-peer`, builds docs/demo/Pages, `npm run test:e2e`, teste E2E Pages, e `openspec validate --all --strict`; conferir CI e Security Gate sobre SHA final da PR Ready. Sem acesso à execução, marcar pendências, nunca assinalar sucesso por inferência. Reversão: reverter apenas alterações do lote 3 numa PR posterior se quebrar compatibilidade.

A migração não cria componentes, stories novos, diferenças responsivas ou mudança visual intencional. Cenários existentes devem continuar válidos nos temas claro e escuro, com foco, teclado e três browsers. Não atualizar baselines visualmente só para tornar CI verde. O changelog registra apenas o efeito de desenvolvimento, com ausência de mudanças públicas.
